1. Clojure 与 ClojureScript 是什么

Clojure 是一门运行在 JVM 上的现代 Lisp 方言，强调不可变数据（immutable data）与函数式编程。ClojureScript 是 Clojure 到 JavaScript 的编译器，共享 99% 的语法与核心库，让同一门语言同时写后端与前端。

本项目的核心哲学：

  • REPL-first：优先在 REPL 中验证想法，再固化到文件。
  • 数据即代码：配置、SQL、路由、组件都是 EDN/Clojure 数据结构。
  • 不可变状态：用 assoc、update、-> 派生新值，而非原地修改。

2. 语法基础

Clojure 代码由 S-表达式 组成：(操作符 参数1 参数2 ...)。以下是实际代码中频繁出现的字面量：

;; 关键字（keyword）用于当键/标签，带冒号
:user_name  :ok  :roles

;; 符号（symbol）用于变量、函数名
user_name  list-users  +

;; 字符串与数字
"若依管理系统"   200   3.14

;; 布尔与 nil
true  false  nil

;; 调用函数：操作符在前
(+ 1 2 3)
(str "Hello, " "Clojure")

3. 核心集合

项目里所有数据结构几乎都是以下四种：

;; vector：索引访问，最常用作列表/参数序列
[1 2 3]

;; list：代码本身，也用于 cons/seq 操作
'(1 2 3)

;; map：键值对，本项目 app-db 的核心
{:user_name "admin"  :status "0"  :roles [:admin]}

;; set：去重集合
#{:user :role :menu}

4. 函数、解构与线程宏

4.1 defn 与 let

(defn greet
  "打招呼"
  [name]
  (str "你好, " name))

(let [x 10
      y 20]
  (+ x y))

4.2 解构

;; map 解构：从 request 中直接取出 identity
(defn list-users
  [{:keys [user-service]} request]
  (...))

;; vector 解构
(let [[a b & rest] [1 2 3 4]]
  [a b rest])
;; => [1 2 (3 4)]

4.3 多态、变参与匿名函数

;; 多态：按参数数量分派
(defn area
  ([r] (* 3.14 r r))
  ([w h] (* w h)))

;; 变参
(defn sum [& nums] (apply + nums))

;; 匿名函数
(fn [x] (* x x))
#(* % %)

4.4 线程宏

线程宏让数据变换从左到右阅读，本项目大量出现在事件处理与控制器中：

;; -> 把值插到第一个参数位置
(-> db
    (assoc-in [:auth :token] token)
    (assoc-in [:auth :loading?] false))

;; ->> 插到最后一个参数位置
(->> menus
     (filter visible-menu?)
     (map menu->antd-items))

;; some-> 遇到 nil 就停止
(some-> token security/parse-token :user-name)

;; cond-> 按条件添加变换
(cond-> items
  (seq search-name) (filter name-matches?)
  status (filter #(= status (:status %))))

8. LLM + nREPL 探索式开发

本项目的开发体验核心不是“保存 → 编译 → 重启 → 测试”，而是长生命周期的 REPL + 即时求值。LLM/agent 在生成代码的同时，可以把它发送到正在运行的后端或前端 REPL，立刻看到效果。下面介绍具体做法。

8.1 什么是 nREPL，它给我们什么

  • 一个长期运行的后端 JVM 进程（clojure -M:dev -m com.ruoyi.core）会在 端口 7000 暴露 nREPL。
  • LLM/agent 通过 clj-nrepl-eval -p 7000 '<form>' 发送代码，得到即时结果；不需要重启服务。
  • 前端同理：运行 npx shadow-cljs cljs-repl app 或浏览器连接 REPL，即可在 ClojureScript 运行时中求值。

这意味着迭代周期从“分钟级”降到“秒级”，尤其适合和 LLM 一起探索：生成候选实现 → 发送求值 → 观察结果 → 根据反馈再生成。

8.2 后端热重载工作流（来自 env/dev/clj/user.clj）

clj-nrepl-eval -p 7000 '(user/rd)'      ; 重载 domain 服务（业务逻辑、HugSQL 查询）
clj-nrepl-eval -p 7000 '(user/rroutes)' ; 重载路由定义文件
clj-nrepl-eval -p 7000 '(user/ra)'      ; 重载所有命名空间
clj-nrepl-eval -p 7000 '(user/rr)'      ; 完全重启 Integrant 系统（halt → go）

选择建议：

  • domain 逻辑、HugSQL、控制器改动 → (user/rd) 最快。
  • 新增/修改路由条目 → 先 (user/rroutes) 让新定义加载，再 (user/rr) 让 Integrant 重新注册路由。
  • 修改 system.edn、组件结构、中间件栈 → (user/rr) 完全重置。
  • 项目结构大改后不确定状态 → (user/ra) 重新加载所有命名空间，再 (user/rr)。

8.3 在线添加 / 修改数据库

步骤：

  1. 在 resources/migrations-sqlite/（以及 resources/migrations/ for MySQL）新增一个 Migratus 迁移文件。
  2. 在 REPL 执行 (user/migrate) 或 (user/reset-db) 应用迁移。
  3. 在 resources/sql/system.sql 添加 HugSQL 查询。
  4. 执行 (user/rd) 重载 domain 命名空间；开发模式下 query-fn 每次调用都会重新加载 HugSQL，新查询立即可用。

最小端到端示例：

-- resources/migrations-sqlite/20250613000000-sys-demo.up.sql
CREATE TABLE sys_demo (
  demo_id   INTEGER PRIMARY KEY,
  demo_name TEXT    NOT NULL,
  create_time TEXT DEFAULT CURRENT_TIMESTAMP
);

-- resources/sql/system.sql
-- :name list-demos :? :*
SELECT demo_id, demo_name, create_time FROM sys_demo ORDER BY demo_id;
;; 在 nREPL 中
(user/migrate)
(user/rd)
((:query-fn (deref state/system)) :list-demos {})
;; => [{:demo_id 1, :demo_name "hello", ...}]

8.4 在线添加新路由

  1. 在 src/clj/com/ruoyi/web/routes/system.clj 新增 Reitit 路由条目。
  2. 在 src/clj/com/ruoyi/web/controllers/system/... 新增控制器函数。
  3. 如需业务逻辑，在 domain service 添加函数。
  4. (user/rroutes) 重载路由定义，然后 (user/rr) 重置系统，新路由注册完成。
  5. 用 curl 或 Swagger UI（/api）验证。
;; system.clj
["/demo/hello"
 {:get {:summary "演示接口"
        :handler (partial demo/hello {:demo-service demo-service})}}]

;; demo.clj
(defn hello [_ _]
  (response/response {:code 200 :msg "ok" :data "hello from nREPL"}))
clj-nrepl-eval -p 7000 '(user/rroutes)'
clj-nrepl-eval -p 7000 '(user/rr)'
curl -H "Authorization: Bearer <token>" http://localhost:3000/api/system/demo/hello

8.5 前端 nREPL：查看与修改 re-frame 状态

连接 shadow-cljs ClojureScript REPL：

npx shadow-cljs cljs-repl app

读取全局状态：

@re-frame.db/app-db
(get-in @re-frame.db/app-db [:users :items])

直接修改 app-db，UI 会自动刷新：

(swap! re-frame.db/app-db assoc-in [:users :query-params :user_name] "admin")
(re-frame.core/dispatch [:users/fetch {}])

从 REPL 分发事件：

(re-frame.core/dispatch [:users/fetch {}])
(re-frame.core/dispatch [:navigate :user])
为什么这能极大提升 LLM 驱动的前端调试效率？因为 LLM 不需要猜测组件状态，它可以直接读取 app-db、修改状态、触发事件，然后观察 UI 行为，再决定下一步修改哪一行代码。

8.6 后端 nREPL 的超级能力

因为 REPL 握着运行中的系统，你可以做很多“非传统”的事：

  • 生成 JWT： 
    (com.ruoyi.infra.security/generate-token 1 "admin" ["admin"] :exp-hours 24)
  • 快速弹出 Swing UI： 
    (javax.swing.JOptionPane/showMessageDialog nil "Hello from nREPL")
;; 也可以搭一个 JFrame + JTextField 快速表单
  • 性能基准测试：Criterium 已在 dev classpath 上： 
    (require '[criterium.core :as c])
(c/quick-bench (your-fn args))
  • 火焰图分析：可临时加入 com.clojure-goes-fast/clj-async-profiler，或用 lambdaisland.classpath 动态注入，然后： 
    (clj-async-profiler.core/profile
  (dotimes [_ 1000] (your-fn args)))

这些操作的共同点是：它们都能访问运行时的真实状态——user/query-fn、state/system、Integrant 组件、数据库连接，全部可用。
