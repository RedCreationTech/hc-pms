若依 Clojure 全栈管理系统

基于 Kit 框架 + ClojureScript + Reagent + Ant Design 构建的 Ruoyi 风格全栈管理后台，对齐原版若依框架核心功能。

项目目标：让开发者专注于业务，降低技术难度，缩短项目周期，并保证软件安全质量。 后端采用函数式、组件化的 Clojure 生态；前端使用 Reagent 2 + React 19 + Ant Design 6， 共享同一端口 3000。

提示
本系统参考 RuoYi-Vue 进行功能对照实现， 在菜单、布局、按钮颜色、操作流程等方面尽量保持一致。

功能模块

系统管理

  • 用户管理：配置系统用户，支持角色、部门、岗位关联
  • 角色管理：RBAC 权限模型，支持菜单/按钮权限、数据权限（部门级）
  • 菜单管理：树形菜单配置，支持路由、组件、权限标识
  • 部门管理：树形部门结构，支持数据权限范围控制
  • 岗位管理：岗位信息维护
  • 字典管理：字典类型与字典数据维护
  • 参数管理：系统运行参数配置
  • 通知公告：系统通知与公告发布

权限控制

  • JWT Token 认证
  • 菜单权限、按钮权限（perms 字段控制）
  • 数据权限：全部、自定义、本部门、本部门及以下

日志审计

  • 操作日志：记录请求方法、URL、参数、结果、耗时
  • 登录日志：记录登录 IP、浏览器、操作系统、登录结果
  • 在线用户：实时监控，支持强退

系统监控

  • 服务监控：CPU、内存、JVM、操作系统、磁盘信息
  • 数据源监控：HikariCP 连接池状态
  • 缓存监控：缓存键值浏览与清除
  • Integrant 依赖图：组件依赖关系可视化与函数调用追踪
  • 定时任务管理：CRON 表达式调度，支持暂停/恢复/立即执行

快速开始

1. 启动后端

默认使用 SQLite，自动迁移并初始化数据。

clojure -M:dev -m com.ruoyi.core

后端运行在 http://localhost:3000，nREPL 端口 7000。

如需使用 MySQL：

JDBC_URL="jdbc:mysql://user:pass@host:3306/ruoyi?useSSL=false" \
MIGRATION_DIR=migrations \
clojure -M:dev -m com.ruoyi.core

2. 启动前端

# 安装 NPM 依赖（首次）
npm install

# 开发模式（自动增量编译）
npx shadow-cljs watch app

前端由后端同一端口 3000 提供服务，编译产物输出到 resources/public/js/。

3. 构建生产包

# 前端发布
npx shadow-cljs release app

# 后端 Uberjar（包含前端静态文件）
clj -T:build all

# 运行
java -jar target/rouyi-standalone.jar

热重载

后端（Clojure）

通过 nREPL 端口 7000 热重载，无需重启进程：

clj-nrepl-eval -p 7000 '(user/rd)'      ; 重载域服务
clj-nrepl-eval -p 7000 '(user/rroutes)' ; 重载路由（需 rr 生效）
clj-nrepl-eval -p 7000 '(user/ra)'      ; 重载所有命名空间
clj-nrepl-eval -p 7000 '(user/rr)'      ; 完全重启系统

前端（ClojureScript）

shadow-cljs watch 已自动编译，保存 .cljs 后刷新浏览器即可。

注意
HugSQL .sql 文件、resources/system.edn、Integrant 组件结构变更后，需要 (user/rr) 或重启后端。

前端组件规范

  • 统一使用 Reagent 2 函数组件 + React Hooks，禁止使用 reagent/atom 管理局部状态。
  • 全局状态使用 re-frame subscription；局部状态使用 hooks/use-state。
  • Ant Design 6 组件必须先定义再使用，例如 (def switch (r/adapt-react-class Switch))。
  • Button 的 :icon 必须是 React 元素，不能传字符串。
  • Dropdown 的 :label 必须用 r/as-element 包裹。
  • 颜色对齐 Element UI：新增 #409eff、修改 #67c23a、删除 #f56c6c、导入 #909399、导出 #e6a23c。

Kit 框架概览

本项目后端基于 Kit 构建。Kit 是一个模块化的 Clojure Web 框架，核心仅提供最小程序基础， 大部分功能通过可选模块或库注入。它使用 Integrant 管理系统组件生命周期， 使用 Reitit 定义路由，使用 Ring 处理 HTTP 请求。

核心文件

文件作用
deps.edndeps 项目配置与依赖管理
build.cljClojure CLI 构建脚本
resources/system.ednIntegrant 系统组件配置
src/clj/com/ruoyi/core.clj应用入口，启动/停止系统
src/clj/com/ruoyi/web/handler.clj路由与请求处理入口
src/clj/com/ruoyi/web/routes/*.clj各模块路由定义
src/clj/com/ruoyi/web/controllers/*.clj控制器层
src/clj/com/ruoyi/web/middleware/*.clj横切中间件

主要 Kit 库

  • kit-core：基础工具函数
  • kit-undertow：基于 luminus-undertow 的 HTTP 服务器绑定
  • kit-sql：SQL 集成（conman、next.jdbc、HugSQL、Migratus）
  • kit-quartz：基于 cronut 的 Quartz 调度器
  • kit-nrepl：nREPL 组件

系统与配置

系统资源（HTTP 端口、数据库连接、查询函数等）在 resources/system.edn 中声明。 Kit 使用 Integrant 读取该配置并启动/停止组件。 

;; HTTP 服务器配置示例
:server/http
 {:port #long #or [#env PORT 3000]
  :host #or [#env HTTP_HOST "0.0.0.0"]
  :handler #ig/ref :handler/ring}

环境相关代码放在 env/dev、env/test、env/prod 下。 env/dev/clj/user.clj 提供 REPL 辅助命令，例如 (go)、(halt)、(reset)。

Reitit 路由

路由是请求处理的入口。每个路由都是 [path handler-map] 的向量， handler-map 的键为 HTTP 方法，值为处理函数。 

;; 基础路由示例
["/" {:get (fn [request] {:status 200 :body "GET request"})
      :post (fn [request] {:status 200 :body "POST request"})}]

;; 带参数的 POST 路由
["/foo/:bar" {:post (fn [{:keys [path-params query-params body-params]}]
                       {:status 200
                        :body (str "path: " path-params
                                   "\nquery: " query-params
                                   "\nbody: " body-params)})}]

静态资源默认由 resources/public 目录通过 ring/create-resource-handler 提供。 路由组织上，建议按业务模块拆分为独立的 *-routes 命名空间，再在 handler.clj 中聚合。

中间件

Kit 使用 Ring / Reitit 中间件。中间件可以包装处理函数，在请求到达控制器前后添加行为。 Reitit 支持将中间件定义为数据，便于组合与追踪。 

;; 数据中间件示例
(def wrap-nocache
  {:name ::wrap-nocache
   :description "Adds Pragma: no-cache"
   :wrap (fn [handler]
           (fn [request]
             (let [response (handler request)]
               (assoc-in response [:headers "Pragma"] "no-cache"))))})

开发专用中间件应放在 env/dev/clj/com/ruoyi/dev_middleware.clj 的 wrap-dev 中， 避免打包到生产环境。中间件顺序很重要： 

(-> handler wrap-formats wrap-defaults)
;; 请求实际经过：wrap-defaults -> wrap-formats -> handler

而通过 Reitit 路由 :middleware 注册的中间件按书写顺序执行： 

["/api" {:middleware [middleware-1 middleware-2]}]
;; 执行顺序：middleware-1 -> middleware-2

数据库

本项目使用 Kit-SQL 模块，以 Migratus 管理迁移、HugSQL 编写查询。 SQL 文件位于 resources/sql/，迁移文件位于 resources/migrations-sqlite/ 或 resources/migrations/。

连接与迁移配置

:db.sql/connection
 #profile {:dev  {:jdbc-url "jdbc:sqlite:rouyi.db"}
           :test {}
           :prod {:jdbc-url #env JDBC_URL}}

:db.sql/migrations
 {:store :database
  :db {:datasource #ig/ref :db.sql/connection}
  :migrate-on-init? true}

:db.sql/query-fn
 {:conn #ig/ref :db.sql/connection
  :filename "queries.sql"}

常用迁移命令

;; 创建迁移
(migratus.core/create (:db.sql/migrations state/system) "add-users-table")

;; 运行待处理迁移
(migratus.core/migrate (:db.sql/migrations state/system))

;; 回滚最后一次迁移
(migratus.core/rollback (:db.sql/migrations state/system))

;; 重置数据库
(migratus.core/reset (:db.sql/migrations state/system))

HugSQL 查询

-- :name get-user-by-id :? :1
-- :doc 根据 id 查询用户
SELECT * FROM sys_user WHERE user_id = :id

-- :name add-user! :! :n
INSERT INTO sys_user (user_name, password)
VALUES (:user_name, :password)

在控制器中通过 query-fn 调用：

(query-fn :get-user-by-id {:id 1})

事务中使用 next.jdbc/with-transaction：

(let [conn (:db.sql/connection system)]
  (next.jdbc/with-transaction [tx conn]
    (query-fn tx :add-user! {:user-name "foo" :password "secret"})))

REPL 交互

REPL 是 Clojure 开发的核心。本项目已配置 nREPL，开发时连接后可通过 user 命名空间控制系统的启动、停止与重启。

方式命令 / 端口
本地 REPLclj -M:dev
nREPLclj -M:dev:nrepl 或默认端口 7000
CIDERclj -M:dev:cider

进入 REPL 后：

(go)    ;; 启动系统
(halt)  ;; 停止系统
(reset) ;; 刷新系统

本项目的 user.clj 还提供了更细粒度的热重载 helper： (user/rd) 重载领域服务，(user/rroutes) 重载路由， (user/ra) 重载所有命名空间，(user/rr) 完全重启系统。

性能调优（async-profiler）

项目已集成 clj-async-profiler 与 criterium，可在 nREPL 中直接调用。

(require 'user.profile-demo)
(user.profile-demo/run-all)

包含两个演示场景：

  • GC 场景：临时对象 (vec (range 1000)) vs 基本类型数组 long-array
  • 反射场景：无 type hint 的 (.size %2) vs 有 type hint 的版本

运行后会生成 target/profile-report.html，包含 Chart.js 对比图表和 async-profiler 火焰图链接。
