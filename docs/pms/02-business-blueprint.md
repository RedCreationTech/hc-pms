# HC PMS 业务蓝图

状态: 通用目标设计. Batch 1 仅包含项目中心, 其他流程需后续实施和业务签收. 下面的默认规则是详细设计建议, 不代表外部系统已承诺接口或企业已批准财务口径.

## 业务链路

| 阶段 | 输入 | PMS 管理行为 | 完成证据 |
|---|---|---|---|
| 立项 | 已评审订单, 合同信息, 项目申请 | 建立项目/团队/结构, 关联来源 | 立项依据与完整责任人 |
| 设计准备 | 需求, 售前资料, 物料信息 | URS 条目化, 工勘, 材料申请, 主计划评审 | 已发布计划和受控需求版本 |
| 研发设计 | 已确认需求 | 跟踪设计任务, DQ, 主机/附件交付 | 已批准的设计交付物与评审 |
| 物料齐套 | BOM, 采购和生产工单 | 缺件追踪, 齐套下钻, 长周期预警 | 可追溯的齐套结果和例外处置 |
| 装配 | 齐套条件及装配计划 | 查看执行, 交检, 装配与测试交接 | MES 执行结果和交接评审 |
| SIT/FAT | 测试计划与条件 | 测试进度, 偏差整改, 报告与确认 | 签认报告及必要整改闭合 |
| 发运 | 发货条件, 外向交货申请 | 审批, 装箱/装车, 缺件, 出口任务 | 发运事实, 清单与批准例外 |
| 现场服务 | 交底资料与现场计划 | 定位/安装/调试/SAT 的计划和反馈 | 现场完成信息与验收证据 |
| 收尾 | SAT, 交付物及遗留事项 | 收尾任务, 决算引用, 归档 | 关闭条件已满足且审计完整 |

阶段可以重叠. 项目生命周期状态, 阶段状态和每个任务状态分别维护, 不用一个状态字段承载全部业务. 全生命周期中的 Testing 和 Delivery 在 V1 目标模型中由测试/交付阶段, 任务和 Gate 表达, 不增设同名项目状态; 这些业务仍属于后续开发批次.

## 项目与计划规则

1. 主项目是团队授权和汇总的基本边界. 子项目, 产品结构和任务均持有主项目归属, 防止跨项目父子关联.
2. 合同级项目和业务单元子项目属于项目概念. 产品线/单机属于结构, WBS 属于工作分解. 树的显示可组合这些对象, 数据模型保持类型差异.
3. 计划包含层次, 负责人, 计划日期, 依赖和交付条件. 正式发布须通过模板现有 BPM 对接的评审, 随后生成不可变基线.
4. 当前编辑版本与已发布基线分开. 变更基线需变更单, 差异和审批记录, 不原地覆盖旧基线.
5. 依赖完成时间, 提前/滞后和工作日历分别建模. 循环依赖必须拒绝; 同一项目的层次树同样不可成环.
6. 聚合进度使用明确的已批准权重和计量单位. 首批只统计项目数量和状态, 不将任意子节点平均值展示为准确业务进度.
7. 会议行动项可以转任务, 保留原会议, 行动项和创建人关联, 重试不会重复生成任务.

## Gate 与交付条件

Gate 是需要责任人作出决定的质量关口, 不是日期里程碑. 采用稳定的语义键及可配置显示编号, 避免把未经确认的编号顺序固化到代码. 前段 G1-G3 与业务关口的对应关系仍待批准模板确认, 本设计不宣称已确定.

候选语义包括需求确认, 设计汇总, 齐套确认, 装配测试交接, FAT 确认, 项目交底和 SAT 确认. DQ 可作为带检查项的关键任务, 是否同时需要 Gate 由批准的项目模板决定.

Gate 检查分为必需检查项, 必需交付物版本, 前置任务, 未关闭的阻塞偏差以及签核人. 系统先验证完整性, 审批人再作出业务决定. `approved` 必须引用具体证据版本; 后续新版本不会悄悄替换旧审批依据. 豁免需要有权审批人, 原因, 适用范围和失效条件, 不作为默认绕过机制.

## URS, 偏差与变更

需求条目记录项目, 类别, 编号, 内容, 必需/期望, 来源和版本. 导入前做整批预检, 输出行级错误, 不静默截断或覆盖编号. 后续追踪矩阵把需求版本连接到设计交付物, SIT/FAT/SAT 测试与偏差, 显示缺失关联而不是假设关联存在.

偏差有类型, 严重度, 责任人, 目标时间, 处理和验证证据. 提交整改不等于已关闭. 风险可转为问题并保留双向来源关系.

内部计划调整由 PMS 发起, 客户合同或交期变更以来源业务系统的批准记录为依据. 变更单覆盖影响分析, 需求/计划/交付物差异, 成本影响和外发同步状态. 暂停保存原状态与受影响范围; 恢复先验证前置条件. 取消保留历史, 不替代删除.

## 申请, 发货与现场服务

原材料, 长周期件, 包材, 直发和外向交货申请从项目任务进入, 关联外部审批单和状态. 不同直发类别可使用不同流程; 已存在发运工作单时应检查冲突. 外部采购或物流更新仅由其权威系统确认.

国内和国际项目使用不同的出口任务适用条件. 清单, 缺件和发运事实分别记录来源与时间. 交底完成截止期和现场任务滞后开始是两种独立规则, 天数和日历由模板配置. 收尾阶段可以只在 PMS 管理, 不强制映射到 ERP 阶段.

## 财务设计与算法边界

四算按主项目, 子项目/产品线, 期间, 币种和版本聚合. 概算是早期预测, 预算是已批准目标, 核算是实际已记账成本, 决算是经确认的结项汇总. 它们是平行口径, 不用后来数据覆盖前期数值.

研发费用分摊的候选算法:

- 对费用池 `pool` 和期间 `period`, 取已批准且可归属的项目研发工时 `h_i`.
- 当 `sum(h_i) > 0`, `allocation_i = pool_amount * h_i / sum(h_i)`.
- 金额用定点十进制, 在币种最小单位舍入. 余差按小数余数从大到小分配, 同值按稳定项目 ID 排序, 确保分摊总额等于池总额.
- 当总工时为 0, 费用进入待分摊状态并报告原因. 不除零, 不默认为平均分摊.
- 直接归属人工成本与共享池分摊独立分类, 同一原始账项只能归入一类, 避免重复计入.
- 源系统修订通过冲销/调整版本处理. 已关账期间需授权重开或下期调整, 不静默重算历史报表.

毛利候选口径为收入减约定成本范围, 毛利率为毛利除以同口径收入. 收入为 0 显示不可计算, 不显示 0% 或 100%. 是否含税, 收入确认, 间接费用和净利公式均需财务签收后启用. 多币种不得直接相加; 保存原币, 汇率, 汇率日期及本位币结果. 变更损失必须追溯到变更和源账项, 不与核算重复相加.

## 集成责任与补偿

| 系统类别 | 权威来源 | PMS 负责 | 失败处置 |
|---|---|---|---|
| CRM | 订单/客户合同, 客户交期, 现场服务反馈 | 项目关联, 发布计划, 交底资料关联 | 入站异常隔离, 映射修复后重放; 不猜测客户承诺 |
| OA | 组织同步, 申请审批事实 | 申请入口, 外部流程号, 结果投影 | 超时显示待同步; 审批状态不能按发送成功推断 |
| ERP | 物料编码/项目外部编码, 采购财务账项 | 计划/任务发布, 财务只读投影 | 来源版本校验, 定期对账, 差异需责任人确认 |
| PLM | 设计执行和归档文件 | 发布任务, 管理交付关系 | 保留来源链接和版本; 文档不可获取时明确标识 |
| MES | 装配/测试执行, 相关物流执行事实 | 任务和计划协调, 执行可视化 | 乱序事件不回退状态, 对版本冲突人工复核 |
| SRM | 供应商承诺和交付进度 | 采购关注项与延期预警 | 保留最后更新时间, 显示过期数据 |
| 物流物料系统 | 装箱/装车/缺件清单和相关状态 | 项目物流视图和追溯 | 清单版本保留; 与 MES 冲突按字段权威矩阵处理 |
| BI | 经确认的分析结果/变更损失 | 引用并解释口径 | 来源缺失不生成估算事实, 不覆盖财务账本 |

接口采用 inbox/outbox 和适配器. 本地批准事务与 outbox 同事务提交; 外发失败不撤销合法批准, 但显示 `pending/partial/failed` 并告知负责者. 以 `(source, event_id)` 去重, 再以来源版本拒绝陈旧更新. 出站每个目标独立确认, 指数退避后进入死信, 人工重放保留原业务键. 对账定时发现丢失/重复/金额差异. 外部不可逆操作采用业务补偿单, 不假装数据库回滚能撤销外部事实.

## 需要业务签收的决策

Gate 模板和编号, 进度权重, 工作日历, 齐套率分母, 替代物料处理, 审批角色/代理, 关口豁免, 财务费用池/税额/汇率及关账, 外部字段权威矩阵, 集成认证和服务等级均需明确责任人. 这些事项不阻止首批项目中心开发, 但会阻止相应后续模块宣称生产就绪.
