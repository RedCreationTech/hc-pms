# 16 权限, 组织与审批流程整改计划 (2026-09-24)

## 背景与决定

2026-09-24 对 "多用户 / 多组织 / 权限菜单配置 / 动态工作流程配置" 做了逐文件代码审计并与若依 (RuoYi-Vue 3.9, RuoYi-Flowable / 芋道 BPM) 对照. 用户确认:

- "多组织" 指 **同一家公司的多个部门**, 不做多租户 (tenant) 隔离; 组织能力在现有部门树上补齐.
- 按 S1 (安全与权限底线) -> S2 (组织, 数据权限与菜单) -> S3 (审批流程可配置) 顺序整改, 完成后录制演示视频, 展示组织, 菜单, 流程的灵活配置过程.
- PMS 业务审批不直接接入现有 Flowable (引擎在独立 H2 库, 与业务库不在同一事务), 而是在业务库内新增可配置的审批策略与审批链; Flowable 继续服务办公表单流程, 同时修复审计发现的缺陷.

## 审计结论摘要

做得好的部分 (保留): PMS 在 "功能权限 + 项目成员范围" 双重校验下工作, 每次请求从数据库读取有效用户, 角色与权限 (停用和撤权下一次请求即生效); 独立审核 (提交人不能审批自己, 只有指定审核人可以决定, 管理员不可代批), 机密文件逐次授权, 财务金额按权限隐藏, 约 185 个 PMS 接口均有权限校验与测试.

## S1 安全与权限底线

- 路由级权限: 系统与办公路由组启用 "实时身份 + 权限声明" 中间件. 每个接口在路由数据中声明 `:perms` (权限字符串或 `:login` 仅需登录), 未声明的接口一律拒绝 (fail closed); 单元测试遍历路由表保证全部声明. 身份每次请求从数据库读取 (有效用户, 有效角色, 有效菜单权限), 与 PMS 同一口径; 拥有 `admin` 角色的超级管理员放行.
- 权限字符串: 补齐若依标准按钮权限 (部门, 岗位, 字典, 参数, 公告, 日志, 在线用户, 定时任务等) 与办公模块缺失的增删改权限, 由迁移登记为菜单按钮并授予超级管理员角色.
- 会话: 令牌携带会话编号 (jti), 过期时间按秒; 会话存 `sys_online` 并在每次请求校验, 30 分钟无访问过期 (滑动), 退出与强退立即失效且重启不丢; 停用, 删除用户, 重置密码与本人改密时撤销该用户其他会话; 在线用户列表只返回会话编号.
- 数据暴露与输入: 用户相关响应剔除密码; 个人信息只允许昵称, 邮箱, 手机, 性别; 注册由参数 `sys.account.registerUser` 控制 (默认关闭), 注册用户无角色; 通用上传改为登录后使用, 服务端生成存储文件名; 下载只接受上传目录内的单层文件名.
- 保护与校验: 超级管理员用户不可被修改, 停用, 重置密码或删除 (本人经个人中心维护); 超级管理员角色不可修改或删除, `admin` 角色标识保留, 只有超级管理员可以授予该角色; 角色名与标识唯一.
- 登录安全: 用户名或密码错误统一提示并记录日志; 连续 5 次失败锁定 10 分钟 (登录日志页可解锁); 参数 `sys.account.captchaEnabled` 为 true 时必须校验验证码, 登录页按参数显示验证码; 密码长度 5-20; 重置默认密码读取 `sys.user.initPassword`.

### S1 实施记录 (2026-09-25)

- 路由: 系统 109 个, 办公 87 个接口全部声明 `:perms`, 由 `web/middleware/authz.clj` 编译期挂载; `authz_test` 遍历路由表保证无遗漏. 新增仅需登录的选项接口 `/system/user/options`, `/system/dept/options`, `/system/post/options` (选人/选部门/选岗位组件使用, 只返回编号与名称), 登录日志解锁 `/system/login-log/unlock/:user_name`.
- 办公流程的个人办理类接口 (待办, 已办, 抄送, 我的流程, 任务详情, 审批/驳回/认领/转办/委派/办结/加减签/退回列表/抄送, 撤回, 取消, 实例轨迹/流程图/打印) 改为 `:login`, 授权来自任务归属: 办理需要是办理人或未认领任务的候选人, 查看需要是实例参与人 (发起人, 抄送人, 历史或当前任务的办理人/所有者/候选人) 或拥有流程管理权限 (`bpm:instance:manage` / `bpm:instance:ops` / `bpm:task:list`); 越权返回业务码 403. 这样流程配置把谁设为审批人, 谁就能办理, 不会因角色缺菜单而卡住流程; 菜单只决定入口是否显示. 发起流程仍需 `bpm:instance:start` 且受模型的可发起人/部门限制.
- "我的流程" 与 "流程实例管理" 原先共用 `bpm:instance:list`, 导致任何能看 "我的流程" 的人可以查全部实例. 迁移把流程实例管理菜单改为 `bpm:instance:manage`; 实例列表对非流程管理员强制只返回本人发起的. `bpm:instance:cancel` 改为挂在流程实例管理下的 "取消任意流程" (发起人取消本人流程不需要该权限).
- 普通角色 (`common`) 默认授予办公自助菜单: 我的流程, 发起流程, 我的待办 (审批通过/驳回/转办/加签/减签/抄送按钮), 我的已办, 抄送我的.
- 修复: 流程实例挂起/激活调用参数错误 (原先必然报错); 驳回到指定节点与未认领任务的办理原先不校验办理人.
- 测试口径: BPM 测试必须使用 `FLOWABLE_JDBC_URL='jdbc:h2:mem:<name>;MODE=MySQL;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE'`. 不带 `DB_CLOSE_DELAY=-1` 时每个测试命名空间重启引擎都会清空内存库, 流程实例编号从头分配而业务库保留旧记录, 造成编号冲突和假失败.

## S2 组织, 数据权限与菜单

- 数据权限: 新增 `sys_role_dept`; 角色数据权限弹窗可保存 5 种范围与自定义部门; 当前用户的可见部门集合 = 各角色范围并集 (全部 / 自定义 / 本部门 / 本部门及以下 / 仅本人). 用于用户列表, 导出, 详情与所有用户写操作 (越权返回 403), 部门列表与部门树.
- 部门: 新增/移动时正确维护祖级并级联子部门; 删除前检查下级部门与人员; 同级名称唯一; 部门负责人改为选择用户 (`leader_id`, 同步显示姓名), 供审批规则 "部门负责人" 使用.
- 菜单: 超级管理员拥有全部启用菜单与 `*:*:*`; 菜单树包含完整祖先链并过滤停用菜单; 侧边栏不显示隐藏菜单; 前端路由守卫对未授权页面显示 403; 角色/菜单变更后, 页面获得焦点或切换路由时刷新权限; 系统管理页面按钮按权限显示.

### S2 实施记录 (2026-09-25)

- 数据权限: 新增 `domain/system/data_scope.clj`, 按用户有效角色的数据范围求并集 (1 全部 / 2 自定义 `sys_role_dept` / 3 本部门 / 4 本部门及以下 / 5 仅本人; 下级按 `parent_id` 递归, 不依赖祖级字段; 没有有效角色只看本人; 超级管理员与任一角色为全部时不过滤). 用于用户列表与导出 (SQL 条件 `scope_all / scope_dept_ids / scope_user_id`), 用户详情, 修改 (含调部门), 停用, 重置密码, 删除, 分配角色, 新建 (目标部门), 导入 (目标部门与被覆盖用户), 部门列表, 部门树, 部门详情/新建/修改/删除 (越权返回业务码 403). 系统内部 (流程候选人解析, 身份同步) 改用不做数据权限过滤的 `list-all-users`.
- 角色数据权限弹窗重写: 5 种范围单选 (附说明), 自定义时勾选部门树, 保存到 `sys_role_dept`; 非自定义范围清空自定义部门; 超级管理员角色不可调整. 原弹窗的单选值不会被提交, 自定义部门从未保存, 已修复. "分配用户" 弹窗原先只能查看且调用未注册事件, 改为 "已分配 / 添加用户" 两个页签, 支持批量取消授权与授权.
- 部门: 新建/移动时祖级 = 上级祖级 + 上级编号并级联更新全部下级 (原实现把子部门祖级算成 "自己祖级 + 子部门编号"); 不能挂到自己或自己的下级之下; 同一上级下名称唯一; 有未停用下级时不能停用; 有下级或有用户时不能删除; 负责人改为选择用户 (`sys_dept.leader_id`, 同步显示名), 流程 "部门负责人" 规则与 Flowable 身份同步按 `leader_id` 解析. 迁移用递归 CTE 修正存量祖级 (种子数据原为空串). 部门列表/角色列表的查询条件原先因字符串键未生效, 已修复.
- 菜单与页面: 侧边栏不显示隐藏菜单 (`visible = 1`, 仍可按地址访问); 前端路由守卫按菜单树计算可访问页面 (含隐藏菜单与 "流程设计/定义版本/发起流程" 等无独立菜单的子页面), 未授权显示 403 页; 切换页面与窗口获得焦点时节流 (3 秒) 刷新权限, 角色菜单调整后无需重新登录. 首页快捷入口只显示有权进入的页面, 问候语显示当前用户昵称.
- 按钮权限: 新增 `frontend/permission.cljs` (`permitted?`/`has-permi?`/`page-allowed?`), `page-toolbar/toolbar-button` 支持 `:perms`; 用户, 角色, 部门, 菜单页面的新增/修改/删除/导入/导出/重置密码/分配角色按钮, 岗位, 字典, 参数, 公告, 定时任务, 登录日志 (删除/清空/解锁/导出), 操作日志工具栏按钮按权限显示. PMS 页面的 `use-permission` 与之共用. 用户管理左侧部门树改用 `/system/user/deptTree` (有用户管理权限即可), 用户表单的角色/岗位选项改用仅需登录的选项接口.
- 角色 "分配权限" 弹窗修复 (浏览器回归时发现, 原先在界面上无法给角色分配菜单): 打开时从未加载菜单树 (树为空), 勾选事件未注册. 现在打开即加载菜单树, 父子联动勾选, 保存的授权集合 = 全选节点 + 半选的上级目录/菜单 (否则子菜单与按钮不可达); 回显时只把叶子节点交给树, 上级的全选/半选由树推导, 因此 "用户管理下取消用户删除" 这类配置可以正确保存和回显. 保存后不再整页刷新, 改为立即刷新当前账号的权限. "分配用户" 的批量授权/批量取消按后端要求以查询参数提交 (原先提交为请求体, 后端返回 400). 角色列表在新增/修改/删除后的刷新沿用搜索条件.

### S3 实施记录 (2026-09-25)

- 审批策略: 平台配置新增类型 `approval-policy` (编码 = 业务类型 `plan-baseline` / `charter` / `cost-version` / `closure`), 复用配置记录的版本化生命周期 (草稿 -> 发布 -> 退役, 发布替换旧版本, 历史留痕), 内置 4 个示例可导入为草稿. 每策略 1 到 6 级, 每级: 名称, 规则 (`dept_leader` 项目所属部门负责人可上溯 0-5 级 / `role` 指定角色可限项目成员 / `project_manager` / `user` 指定 1-20 人 / `submitter_choice` 提交人选择), `any` 或签 / `all` 会签, 可选金额阈值 (仅章程初始预算与费用版本总额), 无审批人时 `reject` 拒绝提交或 `skip` 跳过. 前端在 "模板与规则 > 审批策略" 页签可视化编辑各级规则并预览. 接口: `GET /api/pms/approval-policies` (已发布策略, 供前端判断是否需要审核人), `GET /api/pms/projects/:id/approvals?biz_type=&biz_id=` (项目审批流), `GET /api/pms/approvals/:flow_id` (审批流详情, 项目读者或已轮到的审批人可见), `POST /api/pms/approvals/:flow_id/decide` (`decision` = `approved` / `rejected`, `comment`).
- 审批链: 新增 `pms_approval_flow` 与 `pms_approval_step` (迁移 `202609250003`, 同时重建 `pms_config_record` 的类型约束). 提交时在同一事务按发布策略解析各级审批人 (排除提交人), 保存策略快照 (之后修订或退役策略不影响已发起的审批); 当前级审批人逐级决定, 或签任一人通过即进入下一级, 会签需全部通过, 任一人驳回即驳回 (驳回必须填写意见), 末级通过后调用业务适配器完成批准, 批准时重做原有校验 (计划快照/资源超配/变更, 关闭依据快照与收尾条件). 提交人不能审批, 只有当前级的待处理审批人可以决定, 管理员也不能代批. 未发布策略的类型保持原 "提交人指定一位审核人" 行为; 有审批链进行中时原单人审核接口返回 409. 章程与关闭在策略生效时不再必须指定审核人 (策略含 "提交人选择" 级别时仍需指定).
- 审批参与人只读: `rules/access!` 对已轮到或已处理过的审批人开放项目只读访问 (等待中的后续级别不开放), 写操作仍要求项目成员.
- 统一待办: PMS "我的待办" 新增 "逐级审批" 分组 (可直接通过/驳回), 补齐原先遗漏的费用版本, 计划基线, 关闭与重开审批, 并汇总办公流程待办 (链接到办公 "我的待办"). 费用版本, 章程, 计划基线, 关闭面板显示逐级审批进度.
- 办公流程修复: 发起流程前同步组织身份, 同步按系统当前数据计算应有的角色/部门/岗位/部门负责人成员关系并删除失效的 (原先只在部署时同步且只增不删); 部门负责人成员关系按 `leader_id` 建立, 不再要求负责人属于该部门; 请假与报销发起因缺少实例名/单号参数而失败 (Phase 3 新增列后遗留), 已修复.

## S3 审批流程可配置

- 审批策略 (配置中心 "审批策略" 页签, 版本化: 草稿 -> 发布 -> 退役, 发布即替换旧版本, 已发起的审批使用发起时的快照): 按审批类型 (计划基线, 项目章程, 成本版本, 项目结项) 配置多级审批. 每级: 名称, 审批人规则 (指定角色 [可限本项目成员] / 项目所属部门负责人 [可上溯 N 级] / 项目经理 / 指定用户 / 提交人选择), 会签或或签, 可选金额条件 (达到阈值才需要本级), 无可用审批人时拒绝提交或跳过本级.
- 审批链: 业务库新增审批流与审批步骤表, 与业务状态在同一事务内推进; 提交时按策略解析审批人 (排除提交人), 逐级决定, 任一驳回即驳回, 末级通过后调用原业务状态机完成批准; 未发布策略的类型保持原 "提交人指定审核人" 行为. 独立审核底线保留: 提交人不能审批, 只有当前级审批人可以决定. 审批参与人可只读查看该项目.
- 统一待办: PMS "我的待办" 合并审批链待办, 补上计划基线, 成本版本, 结项, 重开, 并汇总办公流程待办 (链接到办公审批页).
