# HC PMS 开发与验收路线图

状态: 可执行的分批路线, 不含未经测算的日历承诺. 本轮正在开发 Batch 1. 完成状态须由代码, 可运行环境和测试结果证明, 文档本身不算功能交付.

## 批次安排

| 批次 | 可交付闭环 | 主要依赖 | 放行标准 |
|---|---|---|---|
| 1 项目中心 | 项目持久化, 主子单机结构, 成员, 权限内概览, 动态菜单, 状态与审计 | 真实模板启动, 认证和权限, SQLite迁移 | 新建到计划阶段真实操作闭环, 越权拒绝, 非法迁移409 |
| 2 计划与 Gate | WBS/依赖/日历, 发布评审, 基线, 关口检查与证据引用, 变更差异, 受控归档/成员撤销 | Gate模板, BPM接入合同, 计划规则 | 不可变基线, 循环拒绝, 缺证据不放行, 首次开放执行状态 |
| 3 需求与协作 | URS版本/导入/追踪, 文档版本, 会议行动项, 问题风险 | 存储与权限, 文档格式与密级, 模板 | 文档/需求全程追溯, 无权限不能预览, 整改验证后关闭 |
| 4 执行与集成 | 申请和审批投影, 齐套/装配/测试/物流/现场看板, inbox/outbox及对账 | 逐系统接口合同, 沙箱账号, 责任人 | 重复/乱序/失败可恢复, 数据新鲜度可见, 核心事件对账通过 |
| 5 财务和经营 | 四算版本, 工时分摊, 变更损失, 成本及经营看板 | 财务口径签收, 权威数据, 汇率/期间 | 金额守恒, 零工时处理, 账项无重复, 样例与财务对账一致 |
| 6 AI 辅助 | 有证据问答, 摘要, 候选行动与受控写入草稿 | 授权索引, 模型数据策略, 工具合同 | 越权/注入测试通过, 引用可验证, 人工确认及原审批不可绕过 |
| 7 生产就绪 | MySQL验证, 性能容量, 备份恢复, 监控告警, UAT及上线 | 全部目标范围签收, 真实部署条件 | 生产迁移演练, 恢复演练, 关键链路UAT通过 |

Batch 2 先提供 Gate 所需的最小证据登记: 稳定来源引用, 确定版本, 内容摘要和审批快照. Batch 3 再扩展完整文档上传/预览/版本工作台, 避免 Gate 放行依赖尚未交付的证据能力.

Batch 4 应先接入一个窄且可对账的真实事件闭环, 再扩展系统. 不在没有接口合同和测试账号时宣称八套系统联通. AI 先只读试点, 后续写操作以明确 proposal 和正常业务权限实现.

## Batch 1 开发清单

1. 保留模板的 `src/clj`, `src/cljs`, `resources` 结构和现有认证/BPM能力. 在独立 PMS 命名空间扩展, 避免将参考仓库说明误认为已有可复用 PMS 实现.
2. 加入项目, 结构, 成员和审计的迁移及查询. 开发 SQLite 可运行, 同时标明 MySQL目标迁移验证情况.
3. 实现项目接口与业务服务, 统一功能权限和项目范围校验. 用户身份来自认证上下文.
4. 提供状态命令而非任意更新状态. `draft -> initiated -> planning` 可执行, 首批 `planning -> execution` 明确返回409.
5. 对接动态菜单和 ClojureScript 页面, 完成真实创建/读取/编辑, 树和成员角色操作, 使用服务端持久化结果.
6. 概览统计只聚合当前授权项目; 无数据给空态, 不填充虚构进度或财务指标.
7. 验证迁移, 关键API, 权限与状态, 前端编译及浏览器真实操作, 记录结果和剩余局限.

## 首批验收场景

| 场景 | 操作 | 预期结果 |
|---|---|---|
| 基础闭环 | 创建, 刷新, 查看, 编辑项目 | 数据持久化一致, 编码冲突有明确错误 |
| 结构合法性 | 新建子项目和单机, 构造跨项目父节点请求 | 正常层级可读, 非法父子关系拒绝 |
| 团队 | 添加成员/调整角色, 用该用户重新访问 | 生效范围一致, viewer无法写入, 重复关系不重复插入 |
| 数据隔离 | 不在管理员/创建者/负责人/成员范围的用户访问列表, 单ID详情, 树, 成员和统计 | 没有项目泄漏, 写接口同样拒绝 |
| 首批状态 | 立项, 进入计划, 请求执行 | 前两步合法, 执行409且项目仍为planning |
| 取消 | 合法状态取消后再次迁移 | 取消原因和历史保留, 不允许任意恢复 |
| 范围边界 | 检查项目和成员操作入口 | 首批没有项目删除/归档和成员移除, 不返回假成功 |
| 审计 | 创建/编辑/成员/结构/状态操作后读取允许的审计信息 | 行为人, 对象, 时间和动作可追溯, 无敏感凭证 |
| UI | 菜单, 表单错误, 提交失败, 页面刷新 | 可操作并保留输入, 成功反馈与真实响应一致 |

## 测试分层

领域测试验证状态迁移, 父子关系和权限判定等不变量. 数据库测试验证迁移, 唯一性, 事务和授权查询. API测试验证认证, 403/404策略, 409冲突及响应合同. 浏览器测试覆盖真实创建/编辑/团队/结构/状态闭环. 不编写仅复述实现的浅层测试, 不用编译通过替代业务验收.

后续集成采用合同测试, 故障注入和对账; 财务采用财务确认的样例和边界测试; AI采用独立权限/注入/证据评估. 生产前必须用目标 MySQL 版本进行迁移和关键查询测试, SQLite通过不能作为MySQL已通过的证明.

## 发布与运行设计

开发运行与外部系统生产写入分开配置. 新模块的迁移保持可追溯, 避免破坏模板账户和菜单数据. 部署前完成配置样例, 环境变量清单, 数据备份和恢复方案, 日志字段, 健康检查及故障回退说明. 演示数据使用合成内容, 不提交内部蓝图, 原始业务附件, 凭据或客户数据.

生产安全事项包括后端授权一致性, 请求校验, 注入防护, 日志脱敏, 存储访问控制与文件类型限制. 具体平台与容量方案需依据用户数, 项目规模, 附件量, 数据保留及可用性要求测算, 不直接复制参考平台集群规模.

## 当前明确的限制

首批只完成项目中心的起点, 不应宣传全生命周期交付. 基线/Gate未完成前禁止进入执行. 外部系统接口, 四算和AI尚待实现; 其配置, 权限和审计不能用前端假数据代替. 功能矩阵应随每批发布更新为 planned/in_progress/verified, 并链接验证记录, 不因文档完整就标为verified.
