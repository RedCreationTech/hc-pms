# HC-PMS 完整展示流程 (演示剧本)

状态: 2026-09-24 起有效. 本剧本用**同一个设备订单项目**把 PMS 的工作流程从平台模板走到正式关闭, 每一步给出入口, 操作, 预期看到的结果与演示时应说明的边界. 剧本与 `tests/e2e/pms-demo-flow.spec.js` 一一对应: 该用例在隔离后端上真实执行同样的步骤并按顺序截图到 `reports/demo-flow/`, 报告见 [reports/demo-flow/README.md](../../reports/demo-flow/README.md). 剧本只描述已通过验证的功能, 状态口径以 [验收矩阵](11-feature-acceptance-matrix.md) 为准.

## 演示前准备

- 按 [本地启动](../../README.md#本地启动) 运行服务 (SQLite 即可). 首次启动自动迁移并登记定时任务 9001 "PMS进度扫描".
- 两个账号: A 项目经理 (演示用 `admin / admin123`), B 独立审核人 (系统管理 > 用户管理 建一个用户, 角色须含 PMS 项目查询/列表, 计划审批, 质量与治理审批, 工时审批, 财务查看/审批, 项目关闭审批, 机密文档权限). 用两个浏览器会话分别登录; 管理员也不能批准自己提交的记录.
- 平台 `模板与规则` 中 `单机设备订单项目 (TPL-EQUIPMENT)` 须处于已发布 (无则从内置目录 `导入为草稿` 再 `发布`); 若存在强制的项目编码规则, 建项时点 `按规则生成编号`, 否则自填编号.
- 演示日期口径: 项目计划开始日填过去日期 (如 2026-09-01), 这样派生任务会出现逾期提醒与挣值落后, 演示更真实.

## 剧本 (按 reports/demo-flow 截图顺序)

| 步骤 | 入口 | 操作 | 预期看到 | 演示时说明的边界 |
|---|---|---|---|---|
| 1 平台模板 | 项目管理 > 模板与规则 | 查看已发布的 `单机设备订单项目`: 8 个阶段 (权重 + 派生层级 main/sub/machine + 默认工期), 结构 (主机单元/主机#1/附件单元), 8 个 Gate 模板, 团队角色, 文档类别, 交付要求, 收尾清单; 同页有编码规则, 季度目标, 费用池, 封期 | 模板行 `已发布`, 目录可 `导入为草稿` / `发布` / `修订` / `退役` | 模板修订不追溯已实例化项目; Gate 适用编号 G1-G8 与编码规则口径待业务批准 |
| 2 建项 | 项目管理 > 项目中心 > 创建项目 | 填编号 (或 `按规则生成编号`), 名称, 部门, 计划开始/完成 -> 保存项目 | 列表出现新项目, 状态 `草稿` | 外部 OA/CRM 审批自动建项未接入, 演示从手工建项开始 |
| 3 应用模板 | 项目详情 > 项目概况 > 应用项目模板 | 选 `单机设备订单项目`, 填说明 | 概况显示 `项目模板 ... v2`, `阶段 8 / 结构节点 3 / Gate模板 8 / 计划容器 11 / 收尾清单 3`, 项目结构树出现主机单元 > 主机#1, 附件单元 | 每个项目只能实例化一次 (再次应用 409) |
| 4 团队与任命书 | 项目概况 > 维护成员; 需求与治理 > 成员任命 > 签发任命书 | 把 B 加为只读成员 (审批权限来自其功能权限); 签发任命书 | 团队卡片出现成员; 任命书 V1 可 `查看任命书` / 下载, 快照 SHA256 固化 | 再任命保留旧版本 |
| 5 章程 | 需求与治理 > 章程 | A `编制项目章程` (目标/范围/成功标准/发起人) -> `提交审批` 指定 B; B 登录后 `批准` | 章程行 `已批准` | 缺章程时进入执行被 409 |
| 6 URS | 需求与治理 > URS与追踪 | `新增URS需求` 3 条 (验证方式 测试/检验); 也可 `导入URS` 先 `预检CSV` | 台账 3 条, `验证方式覆盖度` 面板 `已声明验证方式 100%` | 需求修订产生新版本, 旧版本不变 |
| 7 证据 | 需求与治理 > 证据版本 | `登记证据文档` (文本); `上传证据文件` 真实 PDF (密级 机密, 类别 设计); 回到 URS 页 `建立需求追踪` URS-01 -> 证据 | 文件行显示大小/类别/密级/SHA256, `预览/下载` 内嵌 PDF 并显示 "服务端复核: 一致"; 追踪矩阵出现连线 | 机密文件对无 `pms:document:confidential` 的用户 403; 受控签发不是法定电子签章 |
| 8 干系人 | 需求与治理 > 干系人与沟通 | `登记干系人` 客户设备部经理 / 质量经理 / 采购接口人; 可加 RACI 与沟通计划 | 干系人台账, 权力-利益象限, RACI 缺 A 时提示缺口 | 沟通计划生成会议只在本地, 不发外部通知 |
| 9 DQ | 需求与治理 > DQ与局部暂停 | `建立DQ关键任务` (交付件 = 证据文档, 3 项检查) -> `填写检查` 全通过 -> `提交签认` 指定 B -> B 签认 | DQ 行 `3/3`, `版本有效`; 若交付件出新版本则显示 `交付件已更新` | -- |
| 10 派生计划 | 计划与执行 > 进度卷积 > 派生主/子/单机计划 | 填说明保存 | 返回 `node_count 3 / main_stage_count 5 / derived_count 15`; `WBS与排程` 表出现 `S1-MAIN..S8-MAIN` 与 `<节点>-<阶段>` 任务, `来源` 列 `模板派生`, 责任人默认项目经理 | 派生只建任务与 FS 依赖, 里程碑手工登记; 重复派生全部跳过 |
| 11 冲突与权重 | 计划与执行 > 进度卷积 | 把主机#1 装配调试 (M1-S4) 工期改长 (WBS 表 `编辑`); `覆盖阶段权重` (合计 100) | 头部 `主子约束冲突 1`, 面板定位 M1-S7 晚于主计划窗口 N 天; 卷积说明 `权重来自项目级覆盖 (模板快照不变)`, 合计不为 100 被 400 | 权重与进度口径待业务批准 (B02 待规则) |
| 12 需求确认 Gate | 需求与治理 > Gate评审 | `发起Gate检查` 选 `需求确认Gate`, `填写检查` 3 项通过并绑定证据, `提交评审`; B `通过`; 主机/附件汇总 Gate 同法 | Gate进展汇总 卡片 `已通过 / 检查 3/3` | 所有必需执行准入 Gate 通过前不能进入执行 |
| 13 立项与基线 | 项目概况 > 确认立项 / 进入计划; 计划与执行 > 审批与基线 > 提交计划审批; B `批准` | 状态条到 `计划`; 基线 `已批准`, 快照不可编辑, `差异` 可对比 | 批准后再改设计形成新修订, 需重新提交 |
| 14 交付配置与进入执行 | 工程交付 > 配置交付要求; 项目概况 > 进入执行 | 配置 工勘 1 次 / 发货前须入库确认 / 交底 +2 天 / 现场滞后 +1 天 / 交底必需; 点 `进入执行` | 状态 `执行中`; 缺章程/基线/Gate 时弹窗给出阻塞原因 | 执行开始后交付配置锁定 |
| 15 启动会 | 需求与治理 > 会议行动 > 登记项目会议 | 类型 `项目启动会`, 会前资料选证据, 基线选计划修订 | 会议行显示 `计划修订 N`; 无会前包/基线被 409 | 纪要可转会后行动项, 行动可 `转为WBS任务` |
| 16 风险 | 需求与治理 > 风险与问题 > 登记项目风险 | 概率 2 x 影响 3, 应对策略 `减轻`, 计划应对日期 | 风险台账, 超阈值时自动升级待独立确认 | 风险发生可 `转问题` |
| 17 备料与齐套 | 工程交付 > 备料与BOM | `新建备料申请` (长周期物料, 节点 主机#1, 任务 主机#1 装配调试, URS-01, 2 行明细) -> 提交/审批 (B); `建立BOM` -> `申请冻结` -> B 批准; `登记齐套` 先留一行缺件 | `整体齐套率 N%`, 节点卷积 (主机#1 / 主机单元), `缺件清单 1 行` 可展开 | 齐套分母 (替代料/分批) 口径待规则 |
| 18 齐套 Gate 与装配 | 需求与治理 > Gate评审 (零件齐套Gate); 工程交付 > 装配交检 | 未通过齐套 Gate 时 `登记开工` 被 409 "阻断关口尚未通过"; 补齐并通过齐套 Gate 后 `登记开工`, `登记步骤` 上岛 / 装配 / 单机交检 / 连线交检, `提交交检` -> B 批准 | 装配行显示各步骤实际日期, 状态 `已批准` | 装配进度 MES 回传未接入, 步骤为本地登记 |
| 19 交接 Gate 例外 | 需求与治理 > Gate评审 | 发起 `装配与测试交接Gate (G5)`, `填写检查`: AT-1..AT-3 通过绑定证据, AT-4 `例外放行 (需说明)` 填说明; 提交, B 批准 | 进展卡 `检查 4/4` + 金色 `例外 1`, 阻断 SIT试验 解除 | 例外缺说明 400/409; 交接项企业口径待批准 |
| 20 SIT/FAT | 工程交付 > 质量试验 | `建立质量试验` SIT (装配 主机#1, 验收标准), `登记结果` 通过附证据, `提交试验评审` -> B 批准; FAT 同法 | 两条试验 `已批准` | 必需项失败自动形成阻塞问题; FAT 需 SIT 先批准 |
| 21 发运 | 工程交付 > 发运签收 | `建立发运计划` (装配, 收货人, 审核 B); `发货前条件` 确认入库 (未确认时 `申请放行` 409); 通过 `FAT确认Gate (G6)` 后 `申请放行` -> B 批准 -> `登记发运` -> B `验证签收` 完整接受 | 发运行 `已完整接受` | 发运/签收日期不得在未来, B 不能是发运人 |
| 22 交底与现场 | 工程交付 > 工勘与现场 | 发运后自动生成 `HO-SHIP-01` (截止 = 发运日 + 2 天); `完成交底` 附文档清单 -> 自动下发 4 条现场任务 (定位/安装/调试/SAT, 计划开始 = 交底 + 1 天); 按序 `开始` / `完成`; `登记工勘任务` -> `提交工勘确认` -> B 批准 | 交底行 `按期完成`; 现场任务 `已关闭`; 工勘 `已批准`, 收尾阻塞消除 | 现场任务不下发 ERP, CRM 回执未接入; 交底自然日/工作日口径待规则 |
| 23 SAT | 工程交付 > 质量试验 | 建立 SAT (需 SIT/FAT 已批准且装配已签收), 登记结果, B 批准 | SAT `已批准`, 交付待办事项清空 | 客户外部签章不冒称 |
| 24 执行反馈 | 计划与执行 > WBS与排程 > 反馈进度 | S1-MAIN 已完成 (实际 2026-09-01 / 2026-09-12); S2-MAIN 处理中 (实际开始) | 任务表 `实际开始/完成` 列; 未来日期与非完成填实际完成被 400 | 反馈独立审核未做 (H06 partial) |
| 25 工时 | 实际工时 > 提交实际工时; B `批准` | 绑定任务与实际工作日 | 工时行 `已批准`, 参与挣值 AC 与费用分摊 | 同日跨项目累计不超 24h; 封期后不能提交 |
| 26 快照与挣值 | 系统监控 > 定时任务 (9001 `执行一次`) 或 计划与执行 > 进度卷积 > 生成进度快照 | 触发扫描 | `挣值与完工预测` 面板 (BAC/PV/EV/AC/SPI/CPI/EAC/ETC, 预测完工), `进度趋势 (快照)` 当日行, 头部 `SPI x` | 价值单位为计划工作日, 早期 AC 很小时 CPI/EAC 失真; 金额口径在增量7 |
| 27 我的待办 | B 登录 > 项目管理 > 我的待办 | 查看 | `待我审批` (章程/基线/Gate/试验...), `我负责的事项`, `系统提醒: 任务逾期` (逾期的现场服务准备任务) | 只写本地待办, 不投递外部消息 |
| 28 四算 | 项目费用 > 新建成本版本 | 概算 / 预算 / 核算 / 决算 各建一版, `添加条目` 或 `工时分摊`, `提交审批` -> B 批准 | `四算拉通` 卡片与差异 (预算-概算 200.00 等) | 费率/汇率/税额口径待规则; ERP 账项未接入 |
| 29 过程看板 | 项目详情 > 过程看板 | 查看 | 需求/文档/齐套/试验/问题/Gate 过程指标 | -- |
| 30 组合看板 | 项目管理 > 项目组合看板 | 展开项目行 | 进度, SPI/CPI, 阶段标签 (覆盖后权重), 齐套, 试验, 问题, 关口, 成本; 结构节点下钻 | 65 项目时 0.3s (批量读取) |
| 31 经营目标 | 项目管理 > 经营目标看板 | 查看季度目标达成 | 版本化目标与达成复算 | 目标口径待批准 |
| 32 全局检索 | 项目管理 > 全局检索 | 关键字 `智能装配单机` | 命中项目/需求/文档并回链 | -- |
| 33 驾驶舱 | 项目管理 > 项目驾驶舱 | 查看 | 项目总数/执行中/逾期/待办等 | -- |
| 34 接口运维 | 项目详情 > 接口运维 | 查看 | 八套外部系统显示 `未配置`; 收件去重/外发死信为本地协议能力 | 真实企业系统适配待合同, 不以模拟冒充 |
| 35 收尾 Gate | 需求与治理 > Gate评审 | 发起 `SAT条件与SAT确认Gate (G8)` 5 项检查, 提交, B 批准; 全部叶任务 `反馈进度` 为已完成; 项目概况 `进入收尾` | Gate进展汇总 8 张卡片全部 `已通过`; 状态 `收尾中` | 仍有未完成叶任务时进入收尾被 409 |

## 演示时不要冒称的内容

- 八套外部系统 (OA / CRM / ERP / PLM / MES / SRM / 销服物料 / BI) 未接入: 自动建项, 订单行, 装配回传, 售后工单, 权威账项都不在演示里; `接口运维` 页如实显示未配置.
- 待规则行 (Gate 适用编号, 编码规则, 交底日历, 齐套分母, 权重/提醒阈值, 财务费率/税额) 当前用工程默认值, 状态保持 `partial / 待规则`.
- 未做的本地能力: 反馈独立审核与偏差措施, 费率生成人工成本与金额口径挣值 (增量7), 多币种/期间关账 (增量7), Docker/K8S 部署件与恢复演练 (增量10), AI 问答 (需模型接入).
- 定时扫描的 06:00 真实 cron 触发只由 Quartz 表达式与 "执行一次" 证明.
